# div — Repo Summary: Business Flow, Structure, Data Flow

*Generated 2026-11-04 from a read of the code and docs in `C:\dev\div`. Where code and older docs differ, the code wins and the difference is noted in "Caveats".*

## 1. What this product is

**div** is a dividend-investing assistant. A user searches a ticker (US or TSX, e.g. `IBM`, `T.TO`). The system then:

1. Shows the ticker's known dividend history (Yahoo, fetched in the browser).
2. **Predicts** the forward dividend schedule and yield, and publishes it to a **public Google Calendar**.
3. On **clicking a calendar row**, runs an AI risk analysis ("could this dividend be cut or raised before it's announced?"). If a *declared* dividend is found, the row is corrected from `Prediction` to `Declared`.
4. Lets the user log **trades** (positions) to track expected dividend income (Postgres).
5. Shows an hourly AI **market briefing**.

**Core invariant: the declared dividend number is a deterministic fact.** It is retrieved from APIs or parsed, never generated by an LLM. LLMs only produce the "leading read" (risk, sentiment, rumor) around that fact.

## 3. Business flow

```
SEARCH ──▶ PREDICT ──▶ CLICK ROW ──▶ (optional) ADD TRADE
```

| UI action | Runs | Writes | LLM |
|---|---|---|---|
| Search ticker | Yahoo fetch in browser | nothing | no |
| **Predict** button | Agent 0 (Agent 1 inside) | **Google Calendar** | 1 research call |
| Click row (Declared) | Agent 2 | reconcile if drift | 1 analyze call |
| Click row (Prediction) | Agent 1, then Agent 2 | reconcile if declared | resolve + analyze |
| Add trade tick | trades API | **Postgres** `div_cal_trade` | no |
| Page load | market summary | none (hourly cache) | agent run (divagent) |

### The three agents
- **Agent 0: predict and publish** (`ser_div_predict_publish.predict_and_publish`).
  1. Facts from the frontend, echoed verbatim.
  2. `age_pattern`: cadence, specials, cut/gap detection, projection. Deterministic.
  3. `age_predictor`: one LLM call over facts, pattern and signals. Declared-check first. Falls back to the pattern as a LOW-confidence prediction, so it never dead-ends.
  4. `ser_forward_rate`: forward dividend and yield, deterministic.
  5. `_plan_events`: one event per ex-date, with collision rank scheduled < confirmed < estimate < prediction. Yahoo's `nextExDate`/`nextAmount` is kept as a 1%-confidence anchor if everything else withholds.
  6. `_publish_all`: upsert to GCal (08:00–09:00 in `CALENDAR_TZ`), then `reconcile_declared`.
  - `publishToCalendar=false` is preview mode and writes nothing.
- **Agent 1: resolve the declared amount.** There is no separate agent today. It is a shared 3-tier substrate in `age_signals.gather_dividend_signals`, used by Agents 0 and 2:
  1. FMP structured API (US).
  2. dividendhistory.org deterministic parse (covers TSX).
  3. LLM extraction from web snippets, as a last resort.
  - Other providers in the same fan-out (Finnhub, Alpha Vantage, Tavily, Yahoo news RSS, Nasdaq calendar) feed the *leading read*, not the declared number.
- **Agent 2: analyze one row** (`ser_div_analyze.analyze_dividend`).
  1. Build grounding from the facts stamped on the row.
  2. Gather signals.
  3. If declared, start `reconcile_declared` in the background.
  4. One LLM call returns `{headline, riskLabel, reasoning, sources}`.
  5. Await the reconcile and set `corrected=true` if the calendar was rewritten.
  - Never raises; degrades to a low-signal read. Cites only URLs it was given.

### Rules to preserve
- `divstatus` is only `Declared | Prediction`. Legacy `Confirmed` is normalized on read, and migration `b3c7d8e9f0a1` rewrites DB rows.
- **Predict never writes Postgres.** Only a Trades tick creates a `div_cal_trade` row.
- A declared row is locked; forward rate never re-prices it.
- Only a declaration may change a Declared row. Stale future Predictions are deleted only after the new series is written.
- Declared numbers are never hallucinated, and tools fail soft.

## 4. Data flow

### 4.1 System view
```
                       ┌──────────────────────── Yahoo Finance ◀──┐
Browser (divreact)     │   (/yahoo/* via Cloudflare Worker /      │ forward-rate fallback
  │ 1 facts ───────────┘    Netlify fn; dev: Vite proxy)          │
  │                                                               │
  │ 2 Basic auth                                                  │
  ▼                                                               │
divcore ──▶ Gemini / Groq / Mistral / CF / NVIDIA (rotating LLM ring)
  │   ├──▶ Signal providers: FMP, Finnhub, AlphaVantage, Tavily, Yahoo RSS,
  │   │                      dividendhistory.org, Nasdaq calendar, Reddit/news
  │   ├──▶ Google Calendar (REST, OAuth refresh token) ◀── SOURCE OF TRUTH
  │   ├──▶ Postgres (Aiven): div_cal_trade, dividends, symbols, chunk tables
  │   └──▶ divagent  (X-Trace-Secret)
  │            ├─ Strands agents ──MCP──▶ divmcp ──▶ Tavily / Exa / Yahoo / dividendhistory.org / web pages
  │            └─ ETL ──▶ Nasdaq Trader, SEC EDGAR, Polygon ──▶ Postgres (nasdaq, nyse, edgar)
```

### 4.2 Predict (write path)
```
Yahoo ─▶ browser facts {price, currency, pastYearDividends[], ttm, yields, companyName, nextExDate/Amount}
  ─▶ POST /div_agent/predict_dividend
  ─▶ pattern (det.) ─▶ signals (providers) ─▶ LLM research ─▶ forward rate
  ─▶ planned events ─▶ GCal upsert (private props: divstatus, amount, confidence, reasoning, sources,
                                    forwardRate, forwardYield, price, priceAsOf,
                                    companyName, currency, ttmAmount, pastYearDividends JSON)
  ─▶ reconcile_declared (Declared overwrites the Prediction row)
```

### 4.3 List and click (read path)
- **List:** `GET calendar_upcoming` reads GCal. `enrich_forward_rates` refreshes any non-Declared symbol whose `priceAsOf != today`: one Yahoo fetch, patched back to the events. The first viewer of the day pays the cost.
- **Click:** the frontend reuses the facts stamped on the row (`factsFromItem`) with **no Yahoo refetch**. A live `fetchTickerProfile` is used only for legacy rows. It then calls `analyze_dividend`. If the response has `corrected: true`, the frontend bumps `calendarRefreshKey` and the row flips to Declared.

### 4.4 Trades
Browser ⇄ `/div_trade/*` ⇄ Postgres `div_cal_trade` (ticker, ex_date, amount, divstatus, quantity, purchase/sell fields, dividend_amount, `dividend_is_estimate`, `google_event_id`, `hidden`).

### 4.5 Market briefing
Browser ⇒ `GET /div_agent/market_summary` (divcore) ⇒ divagent `/market/summary` (1h cache) ⇒ Strands agent ⇒ divmcp `market_news` (Exa) + `market_quotes` (Yahoo) ⇒ `MarketBrief`. Mover percentages are real tool outputs.

### 4.6 Trace console (hidden page)
Browser (`/trace` path, secret) ⇒ divcore `/div_trace/analyze` ⇒ divagent `/trace/analyze` ⇒ NDJSON stream of tagged steps. Gate: shared `TRACE_SECRET`.

### 4.7 Universe ETL (manual, ~twice a year)
`/symbols/refresh` and `/edgar/refresh` upsert the ticker lists. `/edgar/enrich` fills market cap. All are upserts with no deletes, so delisted symbols remain.

## 6. Configuration and security
- Secrets live in `.env` per module and must never be committed or echoed: Tavily, FMP, Finnhub, Alpha Vantage, EOD, Gemini and other LLM keys, Polygon, Google OAuth, DB URLs, `TRACE_SECRET`.
- divcore uses HTTP Basic (`ADMIN_PASSWORD`) on every route.
- divagent endpoints are internal, behind `X-Trace-Secret` and returning 404 on a miss. divcore is the only caller.
- divcore's `config.py` carries real-looking default values (a Google OAuth client ID, a Sheets URL, `ADMIN_PASSWORD="admin123"`, `SECRET_KEY="your-secret-key..."`). Override these in prod.
- Front-end build env (`VITE_ADMIN_PASSWORD`, `VITE_TRACE_SECRET`) is baked into the public bundle, so those are not truly secret.
